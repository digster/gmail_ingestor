# 2026-08-29: Full Gmail message IDs in markdown filenames + YAML escaping fix

## Change 1: `{slug}_{id[:8]}.md` → `{slug}_{message_id}.md`

- **Root cause**: `writer.py` used `email.message_id[:8]`. Not a hash — a slice of a
  time-ordered Gmail ID, so prefixes collide for emails arriving close together.
  6 collisions across 17,007 messages (uniform-random 32 bits predicts ~0.03).
- **Downstream damage**: `ingestor-tools` matched raw files by `startswith` on that
  prefix, merging colliding pairs into one directory. `newsletters-web/build_site.py`
  keyed one record per directory → 5 emails published with the *wrong body* under the
  right headline; 1 ("Tuesday assorted links") absent entirely.
- **Fix**: `writer.py` now uses the full 16-char ID. Filename collisions are structurally
  impossible since `message_id` is the `messages` PRIMARY KEY.
- **No change needed in `ingestor-tools`** — `extract_truncated_id` returns whatever
  follows the last `_`, so it picks up the full ID and its `startswith` match becomes exact.

## Change 2: `id` field added to YAML front matter

- `converter._build_front_matter(message_id, header)` now emits `id: "{message_id}"` as the
  first field. Previously the front matter had **no ID at all**, which is why downstream
  tools had to parse filenames to recover identity.
- Quoted deliberately: 30 live IDs are all digits and would parse back as `int`.

## Change 3 (found during verification): YAML backslash escaping bug

- `_build_front_matter` escaped `"` but not `\`. Inside a double-quoted YAML scalar an
  unescaped `\` swallows the next escape and terminates the string early.
- 16 files were **unparseable**, all from `"\"Mr. and Mrs. Psmith’s Bookshelf\"" <...>`.
  `ingestor-tools` calls `yaml.safe_load`, logs the error, returns `None`, and skips —
  so those 16 emails never reached `../newsletters` at all. Confirmed absent on disk.
- **Fix**: new module-level `converter._escape_yaml`, backslashes escaped before quotes,
  applied to subject / from / to / cc / labels / label_ids.

## Migration (no re-run, no Gmail API)

New `scripts/migrate_full_message_ids.py` — dry-run by default, driven entirely by SQLite:

```
Phase 0 plan      validate every row, detect duplicate targets
Phase 1 rename    17,003 files (journalled first)
Phase 2 database  17,003 markdown_path updates, one transaction
Phase 3 backfill  insert id: "..." into front matter
```

Also `--verify`, `--rollback <journal>`, and `--repair-front-matter [--apply-repair]`.
Backs up the DB with `sqlite3.Connection.backup()` (WAL-safe). Every phase idempotent.

**Executed on live data**: 17,003 renamed, 17,003 DB rows updated, 17,003 `id` fields
inserted, 16 front-matter blocks repaired. Verify: 0 stragglers, 0 mismatches,
0 unparseable, 30 all-numeric IDs confirmed as `str`. Rollback rehearsed on 20 files
first — filenames, DB rows, and file contents all restored byte-for-byte.

**Known drift, left alone**: 3 rows marked `converted` whose markdown *and* raw files are
missing from disk (late-Feb-2026 subscription confirmations, deleted outside the pipeline).
